Important clarification

A Skill is not a new AI model

One of the most common misunderstandings — clear it up now.

01 · WHY SKILLS
✕ MISCONCEPTION

"A Skill is a special AI model trained for React reviews."

Skills do not train or replace the underlying model.

→
✓ REALITY

"A Skill is a reusable instruction package that guides an existing AI model to perform tasks in a particular way."

The model stays the same — the guidance changes.

What changes

  • The instructions available at task time
  • The standards and procedures described
  • The supporting references and templates

What does not change

  • The model weights
  • The model's fundamental capabilities
  • The need to test that the Skill triggers
Remember: a Skill guides an existing model — it does not create a new one.

MODULE 03 · INTRODUCTION TO CLAUDE SKILLS25 / 61
Runtime · progressive disclosure

Understanding Progressive Disclosure

Claude does not need to load every instruction and supporting file immediately — it loads information in stages.

04 · RUNTIME

Think of reading a textbook: you don't read the entire book whenever you have a question. First the table of contents → then the relevant chapter → then, if necessary, the appendix.

THREE LEVELS OF PROGRESSIVE DISCLOSURE

1

Metadata

Skill name and description are available so Claude can identify relevant Skills. Loaded initially.

2

SKILL.md

When the Skill is relevant, Claude loads its detailed instructions. Loaded when needed.

3

Supporting files

References, templates, examples and scripts when the task requires them. Accessed when needed.

Benefit: only the information actually required for the task enters the context — keeping Claude focused and efficient.

Runtime · why it matters

Context, cost & composability

Why loading less is better — and what to expect when Skills overlap.

04 · RUNTIME
▣

Context-window & cost

Loading unnecessary information consumes context-window capacity and can increase processing costs. Progressive Disclosure keeps both under control.

⊕

Skills are composable

Claude may use multiple relevant Skills for one request — combining their knowledge when several are applicable.

Industry understanding

Skill selection is model-driven, so it is not guaranteed that every intended Skill will always trigger. This is why clear descriptions and real-world testing matter.

Clear description → right Skill → right files → right result.

FAQs · Q1–Q3

Prompts, training & activation

The three most common beginner doubts.

08 · FAQ
Q1

Is a Skill the same as a prompt?

No. A prompt is an instruction for one request. A Skill is a reusable package applied to relevant requests. Prompt = task; Skill = training manual.

Q2

Does a Skill train Claude?

No. It does not retrain the model or change its weights. It provides instructions, knowledge and resources at task time.

Q3

Does Claude activate every Skill?

No. It judges relevance. A Skill may not activate if the description is unclear or the request seems unrelated — hence good descriptions and testing.

PromptSkill
Review this React componentReact Code Review workflow
Explain this SQL querySQL Optimization workflow
Generate Python testsPython Testing workflow

FAQs · Q4–Q5

Multiple & conflicting Skills

When more than one Skill is in play.

08 · FAQ

Q4. Can Claude use two or more Skills simultaneously?

Yes. For "Create a secure REST API in Node.js, optimize its PostgreSQL queries, and write unit tests," Claude may need:

Node.js API DevelopmentSQL OptimizationSecurity ReviewUnit Testing

Multiple Skills can work together on a single request.

Q5. What if two Skills give conflicting instructions?

Example: Skill A says "Use JavaScript"; Skill B says "Always use TypeScript."

  • Define clear responsibilities
  • Avoid contradictory rules
  • Establish project-level standards
  • Explicitly describe which requirements take priority
Do not assume conflicting Skills will always be resolved in a predictable way.
MODULE 03 · INTRODUCTION TO CLAUDE SKILLS48 / 61
FAQs · Q6–Q8

Tokens, scripts & databases

What a Skill can and cannot do by itself.

08 · FAQ
Q6

Does a Skill consume tokens?

Yes. Metadata, loaded SKILL.md, reference documents, and requests/responses all use context. This is why Progressive Disclosure matters.

Q7

Can a Skill contain code?

Yes — scripts such as validate.py or check_security.js. But including a script does not execute it; Claude needs an execution-capable environment and tool access.

Q8

Can Skills access databases?

Not by themselves. They can explain queries, but actual access needs an MCP server, database connector, application API, or other authorized tool.

Example: a PostgreSQL Skill provides query instructions, while a PostgreSQL MCP server provides the actual connectivity.

FAQs · Q10–Q11

Custom GPTs & offline use

Different platforms, different possibilities.

08 · FAQ

Q10. Is a Skill the same as a custom GPT?

No. A Skill is a reusable instruction and resource package for compatible agent environments. A custom GPT is a configured assistant inside ChatGPT with its own instructions, knowledge and possible tools. They solve similar problems but have different implementation models.

Q11. Can a Skill work without internet?

Potentially, yes. If the model and execution environment are available locally, and all Skill files and dependencies are local, the Skill can work offline. An online Claude service requires network access to reach its hosted service.

Rule of thumb: the Skill itself is just files — offline capability depends on where the model and tools run.

FAQs · Q12–Q14

Sharing, files & commands

Skills instruct — the environment enables.

08 · FAQ
Q12

Can Skills be shared?

Yes, depending on the platform. Teams can store Skills in Git repos, share folders, distribute approved Skills, or use organization-managed distribution. Creating one personally does not make it automatically available to everyone.

Q13

Can a Skill modify files?

It can provide instructions for modifying code. Actual edits need an environment with file access and editing tools — e.g. Claude Code with the necessary permissions.

Q14

Can it execute commands?

Not merely because a command appears in SKILL.md. Execution depends on the environment, available tools, permissions and the model's decision to use them — e.g. npm test.

Key idea: a Skill is guidance. Real-world effects require the right environment, tools and permissions.

FAQ · Q15

Preventing confidential information exposure

An important enterprise security concern.

08 · FAQ

RECOMMENDED PRACTICES

▸ Never hardcode API keys or passwords in Skill files

▸ Use environment variables or approved secret managers

▸ Apply least-privilege access

▸ Restrict database permissions

▸ Review scripts before deployment

▸ Treat external documents and files as potentially untrusted

▸ Maintain Git access controls

A Skill is not a security boundary. Its instructions cannot replace technical access controls.
