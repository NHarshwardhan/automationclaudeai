Meaning

What is a Plugin?

A package that makes additional capabilities available inside Claude Code.

01 · PLUGINS
A plugin is a package that combines additional capabilities and makes them available inside Claude Code.
Think about installing an application on your mobile phone.
For example, when you install WhatsApp, you get several capabilities together:
Send messages.
Share files.
Make calls.
Share images.
Similarly, a Claude Code plugin can package multiple capabilities together:
Skills:Give Claude specialized instructions.
Hooks:Automatically execute actions when events occur.
MCP servers:Connect Claude to external applications and APIs.
Instead of configuring each capability separately in every project, we can package them together and distribute them as one plugin.

Structure

3. Plugin manifest structure

A manifest describes your plugin.

02 · MANIFEST
A manifest is simply a configuration file that describes your plugin.
For Claude Code, the file is:
product-plugin/ .claude-plugin/ plugin.json
Example:
plugin.json
{
  "name": "product-management",
  "description": "Helps manage company products",
  "version": "1.0.0",
  "author": {
    "name": "Training Team"
  }
}
Let's understand the fields:
FieldMeaning
namePlugin's unique name
descriptionWhat the plugin does
versionCurrent plugin version
authorWho created it
Authentication and API endpoints are not normally fields in this basic plugin.json manifest. In Claude Code, connection details generally belong in the MCP server configuration, often .mcp.json.
.mcp.json
{
  "mcpServers": {
    "product-api": {
      "type": "http",
      "url": "https://example.com/mcp"
    }
  }
}
Here:
  • url tells Claude where the MCP server is.
  • Authentication may be configured separately, depending on the server.
  • The MCP server communicates with your actual application or API.
So, don't confuse the plugin's description with the API connection details.

How the connection works

The plugin packages the integration; a tool performs the API operation.

03 · CONNECTION
User"Add a new product"
ClaudeUnderstands the request
MCP serverCalls the appropriate API
Product Management APISaves the product in the database
The important point: The plugin packages the integration, but the MCP server or other tool performs the actual API operation.
Putting the pieces together
Skill = InstructionsTeaches Claude how to handle product tasks.
MCP = ConnectionConnects Claude to the Product API.

5. Project-scoped plugins vs User-scoped plugins

Personal installation or project installation.

04 · SCOPE
Imagine you have two projects:
Project A: Product Management API
Project B: Student Management API
You install a Product Management plugin.
User-scoped plugin
You install it for yourself.
It is available across your different projects.
Example:
C:\Users\YourName\.claude\
Project-scoped plugin
You install it for a particular project.
It can be shared with teammates through Git when the project configuration is committed.
Example:
Product-Management-API/ .claude/ settings.json
Difference
User scopeProject scope
Personal installationProject installation
Available across projectsAvailable in that project
Not automatically shared with teammatesCan be shared through Git
Stored in user settingsStored in project settings

6. Publishing a plugin for your team or organization

Share once, install everywhere.

05 · PUBLISHING
Publishing a plugin for your team or organization
Imagine you created a Product Management plugin on your laptop.
Now five developers in your company also need it.
You don't want to manually copy the plugin folder to five computers.
Instead, you can share it through a GitHub repository and a plugin marketplace.
Step 1: Create the pluginBuild the plugin folder locally.
Step 2: Push it to GitHubCreate a repository and upload the plugin.
Step 3: Share the marketplaceTeammates add the marketplace.
Step 4: Install the pluginInstall from the shared marketplace.
Step 5: Use itUse the plugin in Claude Code.
