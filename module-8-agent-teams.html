1. What are Agent Teams and When to Use Multi-Agent Orchestration?

One ticket, several responsibilities.

01 · AGENT TEAMS
Agent Teams means multiple AI agents working together to complete one complex task.
Each agent has a different responsibility, and they coordinate their work to achieve one common goal.
IT Support Ticket #1025
High Priority
"My laptop is very slow, Wi-Fi keeps disconnecting, and I cannot open the company application."
One AI agent could investigate all three problems, but that means it needs to handle multiple responsibilities.
Instead, we divide the work among multiple agents:
Main IT Support AgentReceives the employee's ticket and coordinates the work
→
Network AgentWi-Fi problem
→
Hardware AgentSlow laptop
→
Software AgentApplication issue
→
Reviewer AgentChecks all findings and recommendations
Here, different agents investigate different problems, but all work towards resolving the same employee ticket.
What is Multi-Agent Orchestration?
Orchestration means managing and coordinating multiple agents.
It includes:
  • Deciding which agents are required.
  • Assigning tasks to them.
  • Managing their execution.
  • Sharing information between them.
  • Collecting their results.
  • Producing the final output.
When should we use Agent Teams?
Use them when:
  • A task contains multiple independent problems.
  • Different tasks require different expertise.
  • Multiple tasks can run simultaneously.
  • The final result requires checking and validation.
For a simple question like "What is an IP address?", one agent is sufficient. There is no need to create an entire team.

In our IT Support system, we have three important roles. A. Orchestrator Agent

A. Orchestrator Agent
The Orchestrator is responsible for managing the entire team.
It does not necessarily perform all the investigations itself.
Its responsibilities are:
  • Understand the employee's problem.
  • Break the problem into smaller tasks.
  • Assign tasks to appropriate agents.
  • Collect the results.
  • Coordinate the complete workflow.

3. Communication Patterns: Sequential Pipelines, Parallel Fan-out and Feedback Loops

How agents perform their tasks.

03 · PATTERNS
Now we understand that multiple agents are involved.
But how do they perform their tasks?
There are three common communication patterns.
A. Sequential Pipeline
A. Sequential Pipeline
Sequential means agents work one after another.
The next agent starts after receiving the previous agent's output.
IT Support example:
Suppose the company application is not opening.
We organize the workflow:
Diagnostic AgentIdentifies the cause of the application issue
→
Solution AgentSuggests a solution based on diagnostic findings
→
Reviewer AgentChecks whether the solution is correct
Here, the Solution Agent needs the Diagnostic Agent's findings before it can suggest an appropriate solution.
When to use it: When the next task depends on the previous task.

Independent investigations at the same time.

03 · PATTERNS
B. Parallel Fan-out
Parallel means multiple agents work simultaneously rather than waiting for each other.
IT Support example:
The employee reports three problems:
  • Laptop is slow.
  • Wi-Fi keeps disconnecting.
  • Application is not opening.
The Orchestrator assigns the three investigations simultaneously.
OrchestratorAssigns work

NetworkInvestigates Wi-Fi
→
HardwareInvestigates laptop
→

Collect all findingsOrchestrator combines results
All three agents work independently at the same time.
When to use it: When tasks are independent and can be performed simultaneously.
MODULE 08 · AGENT TEAMS08 / 14
Pattern 03

C. Feedback Loops

Correction after review.

03 · PATTERNS
C. Feedback Loops
Feedback loop means an agent receives feedback, corrects its output and submits it again.
IT Support example:
  1. 1. Software Agent recommends reinstalling the application.
  2. 2. Reviewer Agent checks the recommendation.
  3. 3. Reviewer finds that server connectivity has not been checked.
  4. 4. Reviewer sends feedback to the Software Agent.
  5. 5. Software Agent investigates again.
  6. 6. It discovers that the application server is unavailable.
  7. 7. It updates its recommendation.
  8. 8. Reviewer checks the corrected result.
This is a feedback loop.
When to use it: When the first output may be incomplete or needs correction.

Continuity

4. Shared Memory and Context Passing Across Team Members

Reuse findings instead of repeating investigations.

04 · CONTEXT
When multiple agents work together, they need access to relevant information.
Otherwise, every agent may repeat the same investigation.
Let's continue our IT Support example. The Network Agent investigates the Wi-Fi problem and finds: "Wi-Fi driver is outdated."
Should the Reviewer Agent investigate the same Wi-Fi issue again from the beginning?
Not necessarily. It should receive the Network Agent's findings.
A. Context Passing
Context passing means transferring relevant information from one agent to another.
For example:
Network Agent sends its findings
  • Ticket ID: 1025
  • Problem: Wi-Fi disconnecting
  • Finding: Outdated driver
  • Recommendation: Update driver
Orchestrator receives the findings
Reviewer Agent receives relevant information
It can now check the recommendation without repeating the entire investigation.
B. Shared Memory
Shared memory means storing information in a common place that multiple agents can access.
Think of it as a common record of the IT support ticket.
For example:
Ticket ID: 1025

Employee Issue:
Laptop is slow.
Wi-Fi disconnects.
Application not opening.

Network Agent:
Outdated Wi-Fi driver.

Hardware Agent:
High memory usage.

Software Agent:
Application server unavailable.

Status:
Investigation completed.
Waiting for review.
Now the Reviewer Agent can access the information and prepare the final review.
Context Passing vs Shared Memory
Context PassingShared Memory
Transfers information between agentsStores information in a common place
Example: Send Network Agent's findings to ReviewerExample: Common ticket record
Used to communicate informationUsed to retain and access information
Why are they important?
  • Avoid repeating investigations.
  • Reduce unnecessary token consumption.
  • Maintain continuity.
  • Help agents work using previous findings.

5. Failure Handling: Retries, Fallbacks and Escalation Strategies

What happens when an agent fails?

05 · FAILURE HANDLING
What happens if an agent fails?
For example, the Network Agent cannot access the diagnostic tool.
A good multi-agent system needs to handle these situations.
There are three important strategies.
A. Retries
Retry means attempting the same task again when it fails.
IT Support example: The Network Agent tries to retrieve network diagnostic information. But the diagnostic tool is temporarily unavailable. The system tries again.
1First attempt
Failed
Diagnostic tool unavailable.
2Second attempt
Failed
Temporary connection problem continues.
3Third attempt
Successful
Diagnostic information retrieved.
The system should have a maximum retry limit instead of trying endlessly.
B. Fallbacks
Fallback means using an alternative method when the primary method fails.
IT Support example: The Network Agent cannot access its primary diagnostic tool.
The system can use another available method:
  • Ask the employee for the network error details.
  • Check existing network logs.
  • Use another diagnostic tool.
The investigation continues using an alternative approach.
C. Escalation
Escalation means transferring the issue to a human expert or a higher-level support team when the AI cannot resolve it appropriately.
IT Support example: The Software Agent detects that an employee's company account may have been compromised.
The Reviewer Agent identifies this as a serious security concern.
Instead of allowing the AI to make risky decisions, it escalates the ticket to the company's security team.
Difference
StrategyMeaning
RetryTry the same task again
FallbackUse an alternative method
EscalationTransfer the issue to a human expert

6. Cost and Latency Tradeoffs in Multi-Agent Workflows

Why not create 10 or 20 agents for every task?

06 · COST
Now, an important question:
If multiple agents can work together, why not create 10 or 20 agents for every task?
Because using more agents can increase cost and processing time.
Let's understand two terms.
A. Cost
Cost means how much money or resources are required to execute the workflow.
Every AI agent may consume tokens when:
  • Reading its instructions.
  • Understanding the assigned task.
  • Receiving context.
  • Generating responses.
  • Communicating with other agents.
IT Support example: Suppose one agent can investigate a simple Wi-Fi problem. If we create five agents unnecessarily, we may consume more tokens without getting any additional benefit.
Illustrative token consumption
One Agent
2,000 tokens
Five Agents
10,000 tokens
Illustrative numbers only. Actual consumption depends on the model, instructions, context and outputs.
How can we reduce cost?
  • Use only the required agents.
  • Avoid sending unnecessary context.
  • Avoid repeated reviews.
  • Use smaller models for simple tasks.
  • Use normal code or tools for tasks that don't need AI reasoning.

Tradeoffs · Latency

B. Latency

Time taken to complete a task.

06 · LATENCY
Latency means the time taken to complete a task.
Let's compare sequential and parallel execution. Suppose three agents each take 10 seconds.
Sequential execution:
  • Network Agent: 10 seconds.
  • Hardware Agent: 10 seconds.
  • Software Agent: 10 seconds.
Total = 30 seconds.
Parallel execution:
All three agents work simultaneously.
Total ≈ 10 seconds, plus coordination overhead.
Sequential
30 sec
One after another
Parallel
10 sec
At the same time
Illustrative example assuming independent tasks and no significant coordination overhead. Parallel execution can reduce latency, but it may increase token consumption.
Also, the system must wait for the slowest required agent to finish.
Cost vs Latency
ApproachCostTime
Single agentUsually lowerCan be longer for complex tasks
Sequential agentsUsually higherTasks run one after another
Parallel agentsUsually higherCan be faster
Too many agentsPotentially very highCoordination can cause delays
Important takeaway: We should use the minimum number of agents required to complete the task accurately and efficiently.
