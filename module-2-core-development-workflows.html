Element 1 of 4

Action — be specific about the verb

Action tells Claude Code exactly what operation to perform. A verb is an action word.

03 · FOUR ELEMENTS
✕ WEAK ACTIONS
"Fix the code." · "Improve the login." · "Handle the errors." · "Update the function."

These are unclear — they don't explain what change is expected.
▶
✓ SPECIFIC ACTIONS
"Add input validation." · "Refactor to extract validation." · "Sanitize the input."

Claude now knows the exact operation.

Build a precise vocabulary — pick the verb that matches your intent:

Add

Introduce new functionality

Refactor

Improve structure, same behaviour

Extract

Move code into a separate function/module

Replace

Substitute with another implementation

Remove

Delete unnecessary code

Validate

Check input or data is correct

Sanitize

Clean potentially unsafe input

Optimize

Improve performance / resource use

Document

Add explanations or documentation

Practical: "Improve the student registration code." → "Add input validation to the student registration function." Claude knows to add validation, not redesign the whole feature.

Constraints — define requirements and limits

Think of constraints as instructions given to a developer before starting work.

03 · FOUR ELEMENTS
✕ WEAK
"Add error handling."
▶
✓ STRONG
Add error handling that:
• Uses our existing AppError class from src/errors.js
• Logs via our Winston logger — no console.log

TEMPLATE

Write a [function name] function in [file path] that:
• Takes [inputs with types]
• Returns [output with type]
• Handles [edge cases]
• Follows the same style as [reference function]

▸ practical example
Write a calculateStudentResult function in
src/services/resultService.js that:

 • Takes marks as an array of numbers.
 • Returns total marks and percentage.
 • Handles an empty marks array.
 • Rejects marks below 0 or above 100.
 • Follows the style of calculateAttendance().
▸ expected function concept
function calculateStudentResult(marks) {
  if (!Array.isArray(marks) || !marks.length)
    throw new Error("Marks must be a non-empty array");
  if (marks.some(m => m < 0 || m > 100))
    throw new Error("Each mark must be 0–100");
  const total = marks.reduce((a,b)=>a+b,0);
  const percentage = total / marks.length;
  return { total, percentage };
}

calculateStudentResult([80,70,90]);
// → { total: 240, percentage: 80 }
Observe: Claude understands the input, output, validation rules and coding style — instead of generating an arbitrary function.

TEMPLATE

Refactor [function/file] to:
• [Specific improvement 1]
• [Specific improvement 2]
Keep the existing interface unchanged so callers don't break.

▸ before
function registerStudent(student) {
  if (!student.name) throw new Error("Name required");
  if (!student.email) throw new Error("Email required");
  // Save student
}
▸ after
function validateStudent(student) {
  if (!student.name) throw new Error("Name required");
  if (!student.email) throw new Error("Email required");
}

function registerStudent(student) {
  validateStudent(student);
  // Save student
}
Important: Refactoring must preserve expected behaviour. Run existing tests afterwards to verify nothing broke.

"Refactor registerStudent in src/services/studentService.js to extract validation into validateStudent(), remove duplication and improve readability. Keep parameters, return structure and exported interface unchanged."

MODULE 0216 / 88
Patterns 1–2

Specificity & Scope

05 · GOOD VS BAD
PATTERN 1

Specificity

Be precise about the change you want.

✕ BAD
"Make the code better."
✓ GOOD
"Reduce the cyclomatic complexity of processOrder() in src/orders.js by extracting validation into validateOrder()."
What is cyclomatic complexity?
A measure of how many decision paths exist in a function. Too many if conditions make code hard to understand, test and maintain.

Do not say "make it better" — explain exactly what improvement is required.

PATTERN 2

Scope

Boundaries: what to change and how much of the project to touch.

✕ BAD
"Refactor the entire backend."
✓ GOOD
"Refactor the database connection logic in src/db/connection.js to use a connection pool instead of a single connection."
What is a connection pool?
Like a restaurant with several tables ready instead of one — a pool keeps a group of reusable database connections so the app handles multiple requests efficiently.

Give Claude one manageable task at a time in an existing app.

Patterns 3–4

Assumptions & Desired Output Format

05 · GOOD VS BAD
PATTERN 3

Assumptions

Don't assume Claude knows your tech, library or config.

✕ BAD
"Add caching."
✓ GOOD
"Add Redis caching to getUserById in src/services/user.js using the ioredis client in src/db/redis.js. TTL = 5 minutes."
Caching · Redis · TTL
Caching = temporarily storing frequent data for faster retrieval. Redis = an in-memory data store used for caching. TTL (Time To Live) = how long cached data stays valid — 5 minutes here.

Name the project's existing technology instead of letting Claude guess.

PATTERN 4

Desired Output Format

Tell Claude how the answer should be presented.

✕ BAD
"Explain this code."
✓ GOOD
"Explain getUserById in plain English suitable for a junior developer. Cover: what it does, why it uses async/await, and what the error handling covers."
Why specify format?
A beginner wants step-by-step; a senior wants design detail; a tester wants test scenarios; a trainer wants classroom-ready language. Specify audience, language level and format.

State the audience, language level and format of the expected answer.

Patterns 5–6

Preservation Instructions & Completeness

05 · GOOD VS BAD
PATTERN 5

Preservation Instructions

Say which existing parts must NOT change.

✕ BAD
"Rewrite the auth module."
✓ GOOD
"Rewrite auth to use async/await instead of callbacks. Keep the same function signatures and exported interface."
Signature & exported interface
Function signature = its name + parameters. Exported interface = what the module exposes. Renaming getStudent to fetchStudentDetails breaks every file that calls it.

Tell Claude what it can change and what it must preserve.

PATTERN 6

Completeness

Give all important requirements, not a partial instruction.

✕ BAD
"Add a user profile endpoint."
✓ GOOD
"Add GET /api/users/:id/profile in src/routes/users.js: requires authMiddleware; returns name, email, avatar, createdAt; 404 if not found; 403 for another user's profile; integration tests in tests/routes/users.test.js."
Endpoint · Middleware · Integration test
Endpoint = a URL the app uses to provide/accept data. Middleware = code that runs between request and response (e.g. auth check). Integration tests verify parts work together (route + middleware + DB).

Include endpoint, location, auth, response, errors and tests.

Business constraints

In the previous section we learned that constraints are rules Claude must follow. Now: two additional types.

09 · MORE CONSTRAINTS
▣

Meaning

Business constraints are rules defined by an organization about how its application should behave.

They come from the company's business requirements, security policies, customer needs and operational processes.

These are business rules, not simply coding preferences.

ONLINE SHOPPING APP — EXAMPLE RULES

  • A customer cannot place an order without logging in.
  • A customer cannot cancel an order after it has been shipped.
  • Only an administrator can delete products.
  • A user should not be allowed unlimited login attempts.

EXAMPLE PROMPT — LOGIN RATE LIMITING

▸ banking / e-commerce application
Add rate limiting to POST /api/auth/login.

Business rules:
 • Maximum 5 failed attempts per IP within 15 minutes.
 • Lock the account after 10 failures, not just the IP address.
 • Send an email notification when an account is locked.
 • Admin users are exempt from IP-based limiting.
Purpose: prevent someone from repeatedly trying different passwords.

Context · 5 of 6

Let's understand the terms

The vocabulary behind the rate-limiting prompt.

09 · MORE CONSTRAINTS
RATE LIMITING

How many requests?

Restricting how many requests a user or system can make within a specified time.

Security guard: 5 tries / 15 min ⏱

IP-BASED LIMITING

Which connection?

An IP address identifies a device or network connection on the internet. IP-based limiting counts requests from a particular IP.

ACCOUNT LOCKING

Which user?

Temporarily preventing a particular user account from logging in after too many failed attempts.

ADMIN EXEMPTION

Who is exempt?

Administrator users are not affected by the specified IP-based limit — but other security controls must still apply.

Why say "not just the IP"? If someone attacks Rahul's account from different networks, blocking one IP won't stop them. Account-based tracking catches repeated failures against Rahul regardless of the IP address.
⚑ Technical clarification — admin exemption
Admin exemption applies only to the specified IP-based limit. It does not automatically mean administrators bypass all security checks. Account protection and other controls must still follow the organization's policy.

Style constraints · 1 & 2

Strict mode & functional style

Two requirements that change the shape of the generated code.

09 · MORE CONSTRAINTS

① TypeScript strict mode

TypeScript adds static type checking to JavaScript. Strict mode enables extra checks that catch potential mistakes.

▸ weak: any allows almost anything
function getStudentName(student: any) {
  return student.name;
}
▸ strong: a specific interface
interface Student { name: string; }

function getStudentName(student: Student): string {
  return student.name;
}

TypeScript now knows the student must have a name of type string.

② Functional style — no classes

Organize code using functions rather than classes and objects. The prompt asks Claude for the second approach below.

▸ class-based (not wanted)
class StudentService {
  getStudent(id: number) {
    return `Student ${id}`;
  }
}
▸ functional (wanted)
export function getStudent(id: number) {
  return `Student ${id}`;
}

What does iterative prompting mean?

Repeating a process in multiple rounds to improve the result.

Iterative prompting = give Claude an initial instruction, review its output, then give additional instructions to improve the result step by step.

WHY IS IT IMPORTANT?

The first prompt may produce a working solution that still misses requirements. A search function might be:

  • Case-sensitive
  • Searching only the product name
  • Slow with large amounts of data
  • Unable to handle empty input

Instead of starting again, refine the existing solution.
