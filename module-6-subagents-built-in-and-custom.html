The idea

Handle it yourself, or delegate it?

Claude Code can handle a task in the main conversation or delegate it to a specialized subagent.

01 · WHAT IS A SUBAGENT
🧑‍💻

Task 1 · Small task

Ask a developer what archive() does in product.js.

The developer opens one file, checks the method and explains it. Standard prompt.

👥

Task 2 · Big task

Inspect the entire project and identify every file that reads or updates product status.

The project manager assigns this to another developer who independently examines the codebase and returns a summary. Subagent.

This is exactly the idea behind subagents. Both approaches produce an answer — but they work differently internally.

Important clarification

Subagents do not make work disappear

They change where the work happens.

01 · WHAT IS A SUBAGENT
A subagent does not eliminate token consumption. It has its own context window and consumes its own model resources.
📤

What still returns

The main conversation still receives the subagent's returned output. If that output is very large, it can still consume considerable main-context space.

🧩

The real benefit

The detailed intermediate investigation does not all need to enter the main conversation.

Isolation reduces clutter — not the existence of the work.

Understand each difference

Isolation, instructions, models and tools

Four ideas to remember.

01 · WHAT IS A SUBAGENT
🧠

A · Context isolation

Each subagent has its own context window. This helps when investigating many files without bringing all intermediate information into the main conversation.

📋

B · Different system instructions

Explore investigates the codebase. Code reviewer reviews quality and security. Test agent analyses failures. The main conversation might be implementing a feature while a specialist investigates security.

⚙

C · Different models

Main conversation: Sonnet. Simple investigation subagent: Haiku. This can help cost and speed — the model must be available and configured.

🔐

D · Tool permissions

An Explore agent may read and search but not modify. A coding agent may edit and run tests. This separates investigation from implementation.

Frontmatter is the section between two --- lines in a custom subagent Markdown file.

---

description: >

Fields A–D

name, description, model, tools

Identity and basic capability.

04 · CUSTOM AGENTS
A

name

field
name: readme-checker

Unique name used to invoke the agent explicitly. Like an employee's designation.

B

description

field
description: >
  Use this agent when...

What it does and when to use it. Claude uses this for automatic delegation. Be clear — vague descriptions cause wrong selection.

C

model

field
model: haiku

Haiku = simple/fast; Sonnet = general coding; Opus = complex reasoning. Inherits parent model if omitted.

D

tools

field
tools:
  - Read
  - Grep
  - Glob

Allowlist: Read reads files, Grep searches text, Glob finds files by pattern. No Write/Edit here → cannot modify files.

Seven more frontmatter fields.

Blocklist: - Bash. Inherits available tools except listed ones. tools = allowlist; disallowedTools = blocklist.

maxTurns: 5. Limits turns before returning. Prevents repeated searching without progress.

permissionMode: default. Modes: default, acceptEdits, auto, dontAsk, bypassPermissions, plan. Does not replace the tool allowlist.

skills: - api-documentation. Loads skills into the agent context at start.

effort: low | medium | high controls reasoning. background: true runs without blocking the conversation.

Three groups: Identity & instructions = name, description. Capabilities & controls = tools, disallowedTools, permissionMode, maxTurns. Intelligence & context = model, memory, skills, effort, background.

Terminal permission prompts

If a subagent has Bash access and runs a command requiring approval, Claude Code can still show a permission prompt. Being a subagent does not mean automatic, unobserved terminal access.
