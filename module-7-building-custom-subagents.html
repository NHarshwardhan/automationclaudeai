What Is a Custom Subagent?

A specific responsibility

The project manager analogy.

01 · CUSTOM SUBAGENTS
A subagent is a specialized AI assistant that handles a particular task on behalf of the main Claude Code conversation.
Think of the main Claude assistant as a project manager who assigns work to different team members.
For example, in a software company:
🧑‍💻

One developer handles code review.

🧪

One tester checks application functionality.

📝

One technical writer prepares documentation.

🛡

One security specialist checks vulnerabilities.

Each person has a specific responsibility.
Similarly, in Claude Code, we can create custom subagents for specific development tasks.

MODULE 0706 / 38
System prompt

What is a system prompt?

A system prompt is a set of instructions that tells the subagent:

02 · SYSTEM PROMPT
  • What role it should perform.
  • What task it is responsible for.
  • What rules it must follow.
  • What output it should produce.
  • What it should not do.
Think of it as a job description given to an employee.
For example, if we hire a code reviewer, we need to explain what the person should check and how they should report problems.

Inside the file

Inside code-reviewer.md:

Configuration, responsibilities, rules and output format.

02 · SYSTEM PROMPT
code-reviewer.md
---
name: code-reviewer
description: Reviews JavaScript code for bugs, security issues, and code quality. Use when the user requests a code review.
tools: Read, Grep, Glob
---

You are a senior JavaScript code reviewer.

Your responsibilities:

1. Review JavaScript files.
2. Identify potential bugs.
3. Check input validation.
4. Identify security problems.
5. Check code readability and maintainability.

Rules:

- Do not modify any files.
- Do not create new files.
- Report only meaningful issues.
- Mention the file name and line number.
- Explain why each issue is a problem.
- Suggest how to fix it.

Output format:

1. Issue
2. File and line number
3. Explanation
4. Suggested solution

What does this mean?

Tools and MCP servers

Tools give a subagent the ability to perform actions.

03 · TOOLS & MCP
🔧

For example:

  • Read – read file contents.
  • Grep – search for text in files.
  • Glob – find files using patterns.
  • Write – create or modify files.
  • Bash – execute terminal commands.
🔌

MCP servers can provide additional capabilities.

For example:
  • GitHub MCP – interact with GitHub issues and repositories.
  • Filesystem MCP – access permitted files and folders.
  • Custom Product MCP Server – interact with product-related operations.

MCP servers

What about MCP servers?

Suppose our project has GitHub MCP connected.

03 · TOOLS & MCP
We want a github-issue-reviewer subagent to inspect GitHub issues.
Its instructions can specify that it should use the available GitHub MCP tools to retrieve relevant issues.
Important distinction:
  • The tools field controls the tools available to the subagent.
  • MCP server configuration makes MCP-provided tools available to the Claude Code session.
  • Do not assume that writing an MCP server name in a subagent's prompt automatically connects that server or grants access.
The MCP server must already be configured, and the required tools must be available to the subagent.

Choosing a scope

When should we use project scope?

And when should we use user scope?

04 · SCOPE
📁

When should we use project scope?

Suppose we are working on product-management-api.
We create a subagent called product-api-reviewer.

It understands:
  • Our product model.
  • Our API structure.
  • Our project coding standards.
  • Our project-specific review requirements.

This subagent belongs in project scope because it is designed for this particular application.

🏠

When should we use user scope?

Suppose we regularly work on Angular, React, Laravel, and Node.js projects.

We want a general javascript-reviewer that follows our common JavaScript coding standards.

We can place it in user scope so it can be reused across projects.

Important

Information is passed, not shared automatically

Read the full note.

05 · CONTEXT & STATE
Important: A subagent does not automatically share every detail of the main conversation. Claude Code provides the task and relevant context when delegating. If another subagent needs the findings, the orchestrator must pass those findings as part of its task. Also, separate subagent invocations should not be assumed to share persistent state automatically.

Evaluation

What does evaluation mean?

Creating a subagent does not guarantee that it will perform the task correctly.

06 · EVALUATION
We need to test whether it follows its instructions and produces useful results.
For example, our code-reviewer should:
  • Identify real issues.
  • Avoid reporting imaginary problems.
  • Mention file names and line numbers.
  • Follow its read-only restriction.
  • Provide useful suggestions.
Why use sample prompts?
Sample prompts help us test the subagent under different situations.
We can check whether it behaves consistently.

Module 07 · Summary

Key takeaway

You can think of custom subagents as specialized team members inside Claude Code. Instead of asking one assistant to perform every task, we create separate agents for code review, testing, documentation, and other responsibilities.

Each subagent has its own instructions and permitted tools. We decide whether it belongs to one project or should be available across projects.

The main Claude assistant acts as an orchestrator. It delegates work, receives the results, and combines them into a final response.

Finally, we test each subagent with different prompts to confirm that it performs the assigned task correctly and follows its restrictions.

Key takeaway: A good custom subagent needs a clearly defined responsibility, appropriate tools, the right scope, relevant context, and proper testing.
